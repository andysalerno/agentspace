# Kernel — Implementation Plan

## Overview

The kernel is the innermost layer of AgentSpace. It wraps a headless agent CLI (Copilot CLI, Claude Code, Codex, etc.) in a uniform streaming interface. Each kernel instance runs in a Docker container, owns exactly one session, and emits a standard JSONL event stream on stdout.

This plan covers the first milestone: a working kernel abstraction with a Copilot CLI implementation, runnable via a simple `spawn-kernel.sh` script.

## Standard Event Format (JSONL)

All kernels emit the same JSONL format on stdout, one JSON object per line. This is the contract that agent-host (and `spawn-kernel.sh` for now) consumes.

```jsonl
{"type": "session_start", "session_id": "abc123", "kernel": "copilot-cli", "ts": "2026-03-28T12:00:00Z"}
{"type": "status", "status": "busy", "ts": "..."}
{"type": "text_delta", "content": "Hello, ", "ts": "..."}
{"type": "text_delta", "content": "world!", "ts": "..."}
{"type": "tool_call", "tool": "shell", "input": {"cmd": "ls"}, "ts": "..."}
{"type": "tool_result", "tool": "shell", "output": "file1.txt\nfile2.txt", "ts": "..."}
{"type": "status", "status": "idle", "ts": "..."}
{"type": "error", "message": "something went wrong", "ts": "..."}
{"type": "session_end", "ts": "..."}
```

### Event types

| Type | Fields | Description |
|------|--------|-------------|
| `session_start` | `session_id`, `kernel` | Emitted once at the start. `session_id` is generated by the kernel (or relayed from the harness if it provides one). |
| `status` | `status` (busy/idle/error/done) | Kernel status transitions. |
| `text_delta` | `content` | Incremental text chunk from the agent's response. |
| `tool_call` | `tool`, `input` | Agent is invoking a tool. |
| `tool_result` | `tool`, `output` | Result of a tool invocation. |
| `error` | `message` | Non-fatal error or warning. |
| `session_end` | — | Session is complete. Kernel will exit. |

All events include a `ts` (ISO 8601 timestamp).

## Kernel Protocol

A Python `Protocol` defines the structural type contract. Implementations don't need to inherit from it — they just need to match the shape.

```python
class Kernel(Protocol):
    @property
    def name(self) -> str: ...

    @property
    def status(self) -> KernelStatus: ...

    async def start(self, config: KernelConfig) -> None:
        """Spawn the inner harness process."""

    async def send(self, message: str) -> None:
        """Send a user message to the harness."""

    async def recv(self) -> AsyncIterator[KernelEvent]:
        """Yield standard KernelEvent objects from the harness output."""

    async def stop(self) -> None:
        """Gracefully shut down the harness process."""
```

## BaseKernel

A base class that provides shared machinery so harness implementations only need to define the harness-specific bits:

- Spawns a subprocess via `asyncio.create_subprocess_exec`
- Reads stdout/stderr line-by-line
- Calls an abstract `parse_harness_output(line: str) -> list[KernelEvent]` method that each harness implements
- Handles process lifecycle (start, signal, wait)
- Generates `session_start` / `session_end` / `status` events automatically
- Emits events via an `asyncio.Queue`

Each harness subclass implements:
- `harness_cmd(config) -> list[str]` — the CLI command + args to spawn
- `harness_env(config) -> dict[str, str]` — extra env vars for the process
- `parse_harness_output(line) -> list[KernelEvent]` — parse one line of harness stdout into zero or more standard events

## Harness Implementations

### Echo Kernel (`harnesses/echo.py`)

A trivial kernel that doesn't shell out to anything. It just echoes the input message back as `text_delta` events. Used for:
- Testing the kernel infrastructure end-to-end without a real harness
- Testing the Docker/spawn pipeline
- Developing agent-host without needing API keys

### Copilot CLI Kernel (`harnesses/copilot_cli.py`)

Wraps GitHub Copilot CLI (`gh copilot`). The implementation will:
- Shell out to a `gh copilot` invocation (likely piping the prompt via stdin or CLI args)
- Parse the output stream and map to standard `text_delta` events
- Handle Copilot-specific output formatting (stripping ANSI codes, etc.)

Research needed during implementation:
- Exact invocation for non-interactive / headless use of `gh copilot`
- Whether `gh copilot` supports streaming or returns all at once
- Output format details

## Runner (Container Entry Point)

`kernel/runner.py` is the module executed inside the container: `python -m kernel.runner`

Flow:
1. Read config from environment variables (loaded from `.env`)
2. Read the harness type from `KERNEL_HARNESS` env var (default: `echo`)
3. Read the user message from CLI args
4. Instantiate the appropriate kernel
5. Call `start()`, then `send(message)`, then iterate `recv()` and print each event as a JSON line to stdout
6. Call `stop()` and exit

```
ENTRYPOINT ["python", "-m", "kernel.runner"]
```

## Configuration (.env)

All harness-specific config comes from environment variables, typically loaded from a `.env` file mounted into the container.

```env
# kernel/.env.example

# Which harness to use
KERNEL_HARNESS=echo

# Copilot CLI settings (when KERNEL_HARNESS=copilot-cli)
# GH_TOKEN=ghp_...        # GitHub token for gh auth
# GH_COPILOT_MODEL=...    # Model override if supported

# Generic / future harness settings
# LLM_API_KEY=...
# LLM_ENDPOINT=...
# LLM_MODEL=...
```

- Based on `python:3.13-slim`
- Installs `gh` CLI + copilot extension for the copilot-cli harness
- Copies kernel source and installs the Python package
- Entry point is the runner module
- Message is passed as CMD (so `docker run <image> "can you hear me?"`)

## spawn-kernel.sh

A minimal wrapper for development/testing. Replaces agent-host for now.

```bash
#!/usr/bin/env bash
set -euo pipefail

MESSAGE="${1:?Usage: spawn-kernel.sh <message>}"
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"

docker build -t agentspace-kernel "$SCRIPT_DIR"
docker run --rm --env-file "$SCRIPT_DIR/.env" agentspace-kernel "$MESSAGE"
```

Behavior:
1. Builds the kernel image (no-op if cached)
2. Runs a container with `--rm` (auto-remove on exit), passing `.env` and the message
3. JSONL events stream to the terminal
4. Container exits and is removed

## Implementation Order

1. **Project scaffolding** — `pyproject.toml`, package structure, `__init__.py` files
2. **`events.py`** — dataclasses for all event types + `to_jsonl()` serialization
3. **`protocol.py`** — `Kernel` protocol, `KernelStatus` enum, `KernelConfig` dataclass
4. **`base.py`** — `BaseKernel` with subprocess management and event plumbing
5. **`harnesses/echo.py`** — echo kernel (no external deps)
6. **`runner.py`** — container entry point
7. **`Dockerfile`** + **`.env.example`** + **`spawn-kernel.sh`**
8. **Tests** — unit tests for events, echo kernel, runner
9. **Verify end-to-end** — `spawn-kernel.sh "hello"` produces correct JSONL
10. **`harnesses/copilot_cli.py`** — Copilot CLI harness (requires `gh copilot` research + integration)
